# IDE 赛道实测协议

这个协议规定了怎么跑、怎么判定、怎么记录。**目的是让任何人能复现一轮结果。**

---

## 一 · 前置条件

### 环境记录（必填）

每轮实测开始前，先记录：

```markdown
## 测试环境
- 硬件：<CPU / 内存 / 显卡>
- 系统：<版本>
- 浏览器（如适用）：<版本>
- 网络：<境内直连 / 代理，注明出口>
- 测试仓库：<仓库名 + commit SHA>
- 日期：2026-09-29
- 测试账号档位：<免费 / 付费哪个档>
```

**为什么要这么细**：
- 硬件影响编译/索引速度
- 网络影响云端任务
- 仓库 commit 决定测试对象是否可复现
- 账号档位决定能用哪些模型

**不记录环境 = 结果不可复现 = 不收。**

---

## 二 · 任务集设计

### 设计原则

| 原则 | 说明 |
|---|---|
| **基于真实仓库** | 用真实项目，不用玩具代码 |
| **跨文件** | 要能验证"改动是否正确"，不是"能否写出一个函数" |
| **可判定** | 有明确的通过/失败标准 |
| **不预设答案** | 任务描述里不暗示哪种工具更好 |

### 任务清单（5 个）

见本目录下的 `T0*.md`。每个任务包含：
- 目标
- 起始状态
- 验收标准
- 判定规则

---

## 三 · 判定规则

### 三档判定

| 档位 | 标准 |
|---|---|
| **通过** | 所有断言满足，且无人工接管 |
| **部分通过** | 主路径可用，但存在明确缺陷 |
| **失败** | 主路径不通，或需人工接管超过 3 次 |

### 记录三个量化指标

| 指标 | 怎么记 |
|---|---|
| **人工介入次数** | 你中途帮它解决问题的次数 |
| **返工轮次** | 它做完后你发现不对、要求重来的轮次 |
| **完成时间** | 从开始到验收通过的自然时间 |

**只记「通过/失败」不够**。介入次数和返工轮次才是真正体现工具差异的地方。

---

## 四 · 记录格式

每轮一份文件：`runs/YYYY-MM-rN.md`

```markdown
# 2026-09 第 1 轮实测

## 测试环境
（同上）

## 任务与结果

| 工具 | T01 | T02 | T03 | T04 | T05 | 介入合计 | 返工合计 |
|---|---|---|---|---|---|---|---|
| Cursor | 通过 | 部分 | 通过 | 通过 | 失败 | 7 | 3 |
| Claude Code | 通过 | 通过 | 通过 | 通过 | 通过 | 4 | 1 |

## 逐任务记录

### T01 · 仓库上手
- 工具 A：通过（介入 1，返工 0）
  - 观察：<具体描述，不是"表现良好">
- 工具 B：失败（介入 5，返工 3）
  - 失败原因：<具体>

## 失败案例存档

失败的对话记录、报错、卡住的地方，**尽量原文引用**。
这是本仓库最有价值的部分。

## 本轮局限

- 任务集偏向 TypeScript + Three.js 场景，不覆盖其他技术栈
- 单次运行，未重复验证稳定性
- 部分工具的付费档位未开通，测的是免费额度
```

## 五 · 硬性要求

**下面这些不满足，本轮实测不予收录：**

| # | 要求 |
|:--:|---|
| 1 | 有完整环境记录 |
| 2 | 每个任务都有逐工具的判定结果 |
| 3 | 有失败案例（只有成功记录的实测不收） |
| 4 | 有局限说明 |
| 5 | 引用失败细节时原文，不用自己的话概括 |

## 六 · 偏差控制

### 已知偏差来源

| 偏差 | 说明 | 如何缓解 |
|---|---|---|
| **顺序效应** | 后测的工具因为上下文更熟而表现更好 | 打乱顺序，或每轮换顺序 |
| **熟悉度偏差** | 你更熟悉某个工具的用法 | 记录你此前使用经验 |
| **任务选择偏差** | 任务集偏向某些技术栈 | 在局限里明确说明 |
| **投入偏差** | 某工具测试时你更认真 | 尽量按统一脚本操作 |
| **账号档位偏差** | 付费档位和免费档位能力不同 | 记录档位，不跨档比较 |

### 必须记录的

```markdown
## 测试者
- 此前使用过的工具：<列出>
- 此前未用过的工具：<列出>
```

**这是最容易产生不公平的地方，必须写。**

---

## 七 · 结论怎么写

**实测结论不写总分。**

正确格式：

```
在本轮 5 个任务下，X 的介入合计最低（4 次），Y 的通过率最高（5/5）。
本轮任务偏向 TypeScript 大仓库场景，
不能据此推断其他技术栈下的表现。
```

错误格式：

```
X 得分 92，排名第一。  ← 无统一口径
```

**如果必须排序，说明排序依据是什么，并声明局限性。**

## 八 · 数据引用规范

实测数据进正文时：

```yaml
sources:
  - label: 2026-09 第 1 轮实测
    url: https://github.com/<owner>/<repo>/blob/main/tracks/ide/runs/2026-09-r1.md
    kind: docs
```

**实测数据也是数据，必须可回溯。**
